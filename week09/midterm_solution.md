## 문항 1.

### (1) (가)의 출력 결과

```text
9000 3880
```

c1은 VIP이므로 주문 금액 10000원에서 10% 할인된 9000원을 결제한다. c2는 기본 등급이므로 4000원에서 3% 할인된 3880원을 결제한다.

### (2) (나)의 출력 결과

```text
450 194
```

포인트는 실제 결제 금액의 5%를 정수로 변환해 적립한다.

```python
int(9000 * 0.05)  # 450
int(3880 * 0.05)  # 194
```

### (3) (다)의 출력 결과

```text
3600
```

c2의 등급이 VIP로 변경되었으므로 4000원에 10% 할인을 적용한 3600원이 출력된다.

### (4) 책임 위임과 객체 참조 관점에서 설명

`o2.customer`는 c2의 복사본이 아니라 같은 Customer 객체를 참조한다. 따라서 `c2.grade`를 변경하면 o2가 참조하는 고객의 등급도 변경된 상태가 된다.

또한 Order는 할인율을 직접 결정하지 않고 Customer의 `get_discount_rate()`에 그 책임을 위임한다. 처음 결제할 때는 기본 등급이어서 3880원이었지만, 등급 변경 후 다시 계산하면 VIP 할인율을 적용하여 3600원이 된다.

## 문항 3.

### (1) 진단 3단계

**① 무엇이 발생했는가?**

```text
KeyError: '카테고리'
```

DataFrame에서 `"카테고리"`라는 열을 찾지 못해 발생한 오류이다.

**② 어디에서 발생했는가?**

15번째 줄에서 `category_total(sales)`를 호출했고, 해당 함수의 10번째 줄에서 오류가 발생했다.

```python
return df.groupby("카테고리")["매출액"].sum()
```

**③ 왜 발생했는가?**

실제 열 이름은 `"카테고리 "`로 끝에 공백이 있지만, 코드에서는 공백이 없는 `"카테고리"`를 사용했기 때문이다.

판단 근거는 14번째 줄의 출력 결과에 `'카테고리 '`가 나타난다는 점이다. pandas는 두 문자열을 서로 다른 열 이름으로 구분한다. CSV를 읽고 한글 열 이름까지 출력했으므로, 이 오류의 직접적인 원인은 인코딩이 아니라 열 이름의 후행 공백이다.

### (2) 수정 코드와 위치

`load_sales()`의 5번째 줄 직후, `return df` 이전에 열 이름의 공백을 제거하는 코드를 추가한다.

```python
def load_sales(path):
    df = pd.read_csv(path, encoding="cp949")
    df.columns = df.columns.str.strip()
    return df
```

`str.strip()`으로 열 이름 앞뒤의 공백을 제거하면 `"카테고리 "`가 `"카테고리"`로 바뀐다.

## 문항 6. 

### (1) ①에서 위반한 원칙과 피해

**① 개인정보 최소화 및 외부 제공 제한 원칙**

리뷰 분류에 필요하지 않은 휴대전화번호까지 외부 챗봇에 입력하였다. 개인정보가 외부로 전달되어 스팸, 피싱 등의 피해로 이어질 수 있다.

**② 비식별 처리 원칙**

작성자 닉네임과 휴대전화번호 등을 제거하지 않고 실제 데이터를 그대로 입력하였다. 다른 정보와 결합하여 리뷰 작성자가 식별될 수 있다.

**③ 데이터 사용 권한 및 목적 확인 원칙**

지인에게 데이터를 받았다는 사실만으로 외부 AI에 제공할 권한까지 확보되는 것은 아니다. 정보주체의 동의나 이용 조건을 확인하지 않으면 목적 외 이용 문제가 발생할 수 있다.

### (2) 해결되지 않은 이유 2가지

1. 노출된 API 키를 폐기하지 않고 같은 키를 계속 사용하고 있다. 키를 `.env`로 옮겨도 이미 복사된 키의 악용을 막을 수 없고, 과거 커밋에도 키가 남아 있다.
2. `.env`를 먼저 커밋했기 때문에 이후 `.gitignore`에 추가해도 자동으로 추적이 해제되지 않는다. 따라서 환경 파일을 통해 같은 키가 다시 노출될 수 있다.

### (3) 올바른 대응 절차

**1단계: 노출된 키를 즉시 폐기한다.**

팀장에게 보고하고 API 공급자 관리 화면에서 기존 키를 비활성화한다. Git 기록 정리보다 키 폐기를 먼저 수행한다.

**2단계: 피해 범위를 확인한다.**

사용량, 과금 내역, 접근 기록을 확인하여 비정상 호출과 노출 시점을 조사한다.

**3단계: 새 키를 안전하게 발급한다.**

최소 권한과 사용량 제한을 적용하고 환경 변수 또는 시크릿 저장소에서 관리한다.

**4단계: `.env`의 Git 추적을 해제한다.**

먼저 `.gitignore`에 다음 규칙을 등록한다.

```gitignore
.env
.env.*
!.env.example
```

이미 추적 중인 `.env`는 다음과 같이 처리한다.

```powershell
git rm --cached -- .env
git add .gitignore app.py
git commit -m "security: remove tracked env and protect secrets"
```

현재 추적 상태를 확인한다.

```powershell
git ls-files | Select-String '(^|/)\.env($|\.)'
```

**5단계: 과거 커밋의 비밀정보를 정리한다.**

팀과 협의하여 히스토리 정리 도구로 과거 `app.py`의 키와 `.env` 기록을 제거한다. 히스토리 재작성은 팀원에게 공지하고 재동기화한다. 다른 사람이 복사했을 가능성이 있으므로 기존 키는 다시 사용하지 않는다.

**6단계: 개인정보 전송 문제에도 대응한다.**

데이터 제공자와 학교·팀 담당자에게 보고하고, 챗봇 서비스에 삭제 요청 등 가능한 조치를 수행한다.

**7단계: 재발 방지 조치를 적용한다.**

시크릿 탐지, 커밋 전 검사, 비용 알림을 적용하고 조치 결과를 기록한다.

## 문항 7. 

### (1) 적합한 프롬프트 기법

**① Few-shot**

올바른 JSON 예시를 직접 보여 주어 키 이름과 출력 형식을 일정하게 유도하는 방식이기 때문이다.

**② CoT**

반품 사유, 상품 상태, 경과일 등 여러 조건을 단계적으로 점검하도록 하여 복잡한 판단을 나누는 방식이기 때문이다.

**③ System Prompt**

역할과 공통 규칙을 시스템 수준에서 지정하여 모든 요청에 일관되게 적용하는 방식이기 때문이다.

### (2) temperature 설정

`temperature=0.9`는 출력 변동성을 높여 반복 분류와 JSON 형식의 일관성을 떨어뜨릴 수 있으므로 **0~0.2**를 권장한다. 다만 낮은 값도 정확성과 형식을 보장하지 않으므로 JSON 스키마 검증과 실패 처리를 함께 적용해야 한다.

### (3) 공격 유형과 방어

**공격 유형: 간접 프롬프트 인젝션**

외부 CSV의 리뷰 본문에 포함된 지시가 원래의 분류 지시를 무시하도록 유도하기 때문이다.

**방어 ① 입력 검증 및 지시·데이터 분리**

CSV의 필수 열과 길이 등을 검증하고 리뷰 본문은 비신뢰 데이터로 구분하여 전달한다. 리뷰 속 명령은 실행하지 않고 분석 대상 텍스트로만 취급하도록 시스템 규칙에 명시한다.

**방어 ② 출력 검증 및 권한 제한**

응답의 JSON 키, 타입, 허용된 라벨을 검증하고 실패하면 재시도 또는 수동 검토로 보낸다. 또한 분류 모델에는 불필요한 파일·네트워크·비밀정보 접근 권한을 주지 않는다.

형식이 정상이어도 분류 결과가 왜곡될 수 있으므로 표본 검수와 분류 분포 이상 감시도 함께 수행한다.

| `pop_generator.py` | `generate_pop(item, discount_rate)` **※ mock** | 승인된 할인 정보를 이용하여 POP 초안 JSON을 생성한다. |
| `pop_generator.py` | `validate_pop_output(raw)` | 응답의 키·타입·길이와 판매가 일치 여부를 검사한다. |
| `app.py` | `render_dashboard()` | 업로드, 집계 결과, POP 검토 화면을 제공한다. |

#### LLM 함수 입력·출력

`generate_pop()` **※ mock**

입력:

```json
{
  "product_name": "우유",
  "expiry_date": "2026-10-22",
  "original_price": 2000,
  "discount_rate": 0.2,
  "sale_price": 1600
}
```

출력:

```json
{
  "headline": "우유 할인 행사",
  "body": "유통기한 2026-10-22 상품을 1600원에 판매합니다.",
  "sale_price": 1600
}
```

출력 계약은 다음과 같이 정한다.

- 키는 `headline`, `body`, `sale_price`로 제한한다.
- `headline`은 비어 있지 않은 문자열이며 최대 30자이다.
- `body`는 비어 있지 않은 문자열이며 최대 120자이다.
- `sale_price`는 bool이 아닌 정수이며 코드에서 계산한 승인 판매가와 같아야 한다.
- 할인 판매가는 코드가 원 단위 내림으로 계산한다.
- LLM은 가격이나 유통기한을 결정하지 않고 문구만 작성한다.
- 개발 중에는 고정 JSON을 반환하는 mock으로 대체한다.
- 점주가 검토한 후 POP를 사용한다.

### (3) 핵심 함수 설계

#### ① 함수 시그니처

```python
from datetime import date
import pandas as pd


def find_expiring_items(
    df: pd.DataFrame,
    reference_date: date,
    days: int = 3,
) -> pd.DataFrame:
    ...
```

#### 설계 기준

- `0 <= 남은일수 <= days`인 상품을 포함한다.
- 오늘 만료와 정확히 3일 후 만료를 포함한다.
- 이미 만료된 상품과 수량 0인 상품은 제외한다.
- 예상손실액은 `수량 * 단가`로 계산한다.
- 예상손실액 내림차순, 유통기한 오름차순, 상품코드 오름차순으로 정렬한다.
- 동일 상품코드라도 유통기한이 다르면 허용한다.
- 동일 상품코드·유통기한의 중복 행은 오류로 처리한다.
- 입력 DataFrame은 직접 변경하지 않는다.

#### ② Pseudocode

```text
FUNCTION find_expiring_items(df, reference_date, days = 3)

    IF df IS NOT DataFrame THEN
        RAISE TypeError
    END IF

    IF reference_date IS NOT date OR reference_date IS datetime THEN
        RAISE TypeError
    END IF

    IF days IS NOT 정수 OR days IS bool THEN
        RAISE TypeError
    END IF

    IF days < 0 THEN
        RAISE ValueError
    END IF

    required = [상품코드, 상품명, 카테고리, 수량, 단가, 유통기한]

    IF 필수 열 누락 OR 열 이름 중복 THEN
        RAISE ValueError
    END IF

    work = COPY(df)
    result = 원래 열과 남은일수, 예상손실액 열을 갖는 빈 표
    seen = 빈 집합

    IF work IS EMPTY THEN
        RETURN result
    END IF

    FOR EACH row IN work

        IF 상품코드, 상품명, 카테고리에 결측 또는 공백 존재 THEN
            RAISE ValueError
        END IF

        expiry = 유통기한을 YYYY-MM-DD로 엄격하게 변환

        IF 날짜 형식 오류 OR 존재하지 않는 날짜 THEN
            RAISE ValueError
        END IF

        quantity = 수량을 숫자로 변환
        price = 단가를 숫자로 변환

        IF 변환 실패 OR bool OR 결측 OR 무한대 THEN
            RAISE ValueError
        END IF

        IF quantity < 0 OR quantity가 정수가 아님 OR price < 0 THEN
            RAISE ValueError
        END IF

        key = (상품코드, expiry)

        IF key IN seen THEN
            RAISE ValueError
        END IF

        ADD key TO seen

        remaining_days = (expiry - reference_date)의 일수

        IF quantity > 0 AND 0 <= remaining_days <= days THEN
            loss = quantity * price

            IF loss가 유한하지 않음 THEN
                RAISE ValueError
            END IF

            ADD row WITH 남은일수 = remaining_days,
                         예상손실액 = loss
            TO result
        END IF

    END FOR

    SORT result BY 예상손실액 내림차순,
                   유통기한 오름차순,
                   상품코드 오름차순

    RESET result INDEX
    RETURN result

END FUNCTION
```
